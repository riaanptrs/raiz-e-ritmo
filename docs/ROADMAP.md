# Delivery roadmap

## Milestone 1 — Verified astronomical planner

Implemented on the review branch: PT-BR month/day navigation, 2027 USNO phases, JPL-derived apsides, checked nodes and declination, IAU sky regions, astronomical seasons, explanatory guides, independent hemisphere/time-zone controls and PWA caching. The only agricultural timing rules included are the explicitly partial Stella Natura lunar-node and perigee windows. See [validation evidence](VALIDATION_2027.md).

Review and merge the implementation before configuring a public launch. GitHub Pages is not automatically enabled or deployed by this change. The site is free to use. The project grants no reuse license for its original code, writing or illustrations. Verify installation and offline behaviour on intended phones.

## Milestone 2 — Personal garden notebook

Add optional device-local crop and observation records, with export/import and a clear explanation of data persistence. Record planting, weather observations, soil and outcomes separately. A diary supports learning; it does not establish a planetary cause.

## Milestone 3 — Documented agricultural calendar

Select a complete source or openly specified method. Resolve numerical boundaries, adjustments, avoided periods, time basis, hemisphere conventions and redistribution terms. Audit every imported transition. Display the method and edition, preserving disagreements and uncertainty.

## Milestone 4 — Regional guidance

The practical guide introduces preparation timing by stage of work (500 before sowing, 501 on growing plants, 502–507 during composting), with citations to the consulted edition. Before adding crop-specific preparation instructions, identify a protocol with its edition, eligible crops, conditions, timing and safety guidance, then review those details against the source. Treat any proposed astronomical trigger as a separate rule requiring documentation and validation. Add reviewed regional crop guidance and separate vermicompost instructions. Consider a weather integration only with documented coverage, freshness and failure behaviour. Evaluate reminders after useful, verified task guidance exists.

GitHub Pages is the initial deployment target. A native app-store release, accounts and cloud synchronization can be evaluated later from actual user needs.
